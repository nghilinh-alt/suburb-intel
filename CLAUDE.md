# suburb-intel — Project Memory

## Data Refresh Schedule

| Dataset | Frequency | How |
|---------|-----------|-----|
| **ABS data** (census metrics, SA2 boundaries) | Yearly — check for new releases | Re-run ABS ingestion loaders |
| **Overture Maps** (amenity counts — `osm_*` columns) | Monthly — check for new releases | Update `_OVERTURE_RELEASE` in `backend/app/ingestion/overture_amenity_loader.py`, then run `python -m app.ingestion.overture_amenities --download` followed by `python -m app.ingestion.overture_amenities` |
| **GTFS** (PT stop counts) | Quarterly or when state feeds update | Re-run per-state GTFS loaders |
| **Building Approvals** (ABS SA2) | Yearly — new FY zip released ~May each year | Download new zip from ABS latest release page, re-run `python -m app.ingestion.building_approvals --zip <new_zip>` |
| **Population Projections** (ABS ArcGIS) | Yearly — ABS updates the feature service | Re-run `python -m app.ingestion.population_projections` |
| **Infrastructure Australia Priority List** (PDF) | Yearly — new IPL released each year | Download new PDF to `data/infrastructure/`, re-run `python -m app.ingestion.infrastructure --pdf ../data/infrastructure/<new_pdf>` |
| **iPAMS** (Commonwealth infrastructure projects) | Yearly — live ArcGIS feed, refresh annually | Re-run `python -m app.ingestion.ipams` (fetches directly from `spatial.infrastructure.gov.au`) |
| **Distance to CBD** (`distance_to_cbd_km`) | Only when SA2 boundaries change (tied to the yearly ABS boundary release) — not on its own schedule | Re-run `python -m app.ingestion.cbd_distance --force` after re-loading geometries |
| **PropRadar sold listings** (`property_sales`) | Weekly — matches PropRadar's own "sold records typically appear within a week" cadence | Re-run `python -m app.ingestion.propradar_sold --state <STATE>` (current plan quota = 5,000 calls/month — this endpoint paginates per suburb, so cost varies with sales volume; still scope with `--state`/`--suburb` for predictable spend, an unscoped national run could burn a large chunk of the monthly budget in one go). Requires `PROPRADAR_API_KEY` in `.env`. |
| **School locations** (`local_schools` — name/type/coordinates, no ratings) | Monthly — tied to the Overture Maps release cadence | Update `_OVERTURE_RELEASE` in `backend/app/ingestion/school_locations_loader.py` to match `overture_amenity_loader.py`'s, then run `python -m app.ingestion.school_locations --download` followed by `python -m app.ingestion.school_locations`. Also backfills `sa2_regions.adjacent_sa2_codes` (skips SA2s that already have it — pass nothing to just top up new ones). |
| **School ICSEA ratings** (`avg_school_icsea`/`num_schools` on `abs_census_metrics`) | Yearly — new ICSEA release each year | Needs the raw ACARA "School ICSEA Scores" file, gated behind commercial-use terms (see `school_icsea_loader.py` docstring) — get it via ACARA's Data Access Program, drop in `data/datapacks/`, re-run `python -m app.ingestion.school_icsea --icsea ... --mb data/datapacks/MB_2021_AUST.xlsx --poa data/datapacks/POA_2021_AUST.xlsx`. Afterwards, refresh the committed fallback seed with `python -m app.ingestion.school_icsea_seed_export` (writes `data/seeds/school_icsea_by_sa2.csv` — SA2-level averages only, not the raw per-school list; see that loader's docstring for the licensing reasoning). On a fresh clone without the gated file, run `python -m app.ingestion.school_icsea_seed` to restore from that committed seed instead. |
| **Per-school ratings** (`school_ratings` — sector, per-school ICSEA + ACARA's own percentile) | Same cadence as School ICSEA ratings above, same source file | Re-run `python -m app.ingestion.school_rating --icsea ... --mb data/datapacks/MB_2021_AUST.xlsx --poa data/datapacks/POA_2021_AUST.xlsx` (same raw ACARA file as the aggregate loader — not committed to git, same gating). No seed fallback yet — if that matters, follow the same pattern as `school_icsea_seed_export.py`. |
| **Points of interest** (`points_of_interest` — hospitals, shopping centres, stadiums/arenas, attractions) | Monthly — tied to the Overture Maps release cadence | Update `_OVERTURE_RELEASE` in `backend/app/ingestion/points_of_interest_loader.py` to match `overture_amenity_loader.py`'s, then run `python -m app.ingestion.points_of_interest --download` followed by `python -m app.ingestion.points_of_interest`. Note: use `shopping_center` (US spelling), not `shopping_mall` — the latter has zero matches in Australia's Overture data (this also means `overture_amenity_loader.py`'s existing `osm_shopping_centres` count column has likely been silently 0 for every suburb — not fixed here, flagged for awareness). Hospital entries are filtered to names containing "hospital" (Overture's raw `hospital` category is noisy — ~60% of raw matches were vet/podiatry/radiology/breast-screening clinics, not hospitals). |
| **PropRadar suburb market stats** (`suburb_market_stats` — pre-computed medians/growth/yield/days-on-market/vacancy/heat-score per real suburb, one snapshot row per suburb per calendar month so history accumulates over time) | Monthly — matches PropRadar's own snapshot cadence (`as_of` field) | Re-run `python -m app.ingestion.suburb_market_stats` with no scope flags for a full national refresh (one API call per real suburb, no pagination — ~3,642 calls covers every suburb in the db, comfortably inside the 5,000 calls/month plan quota with room to spare; scope with `--state`/`--suburb`/`--sa2-codes` only if you want a partial refresh). Requires `PROPRADAR_API_KEY` in `.env`. Splits combined SA2 names the same way as `propradar_sold_loader.py` (one row per real suburb) — harmlessly 404s on compass-qualifier SA2 names like "Mernda - North" since "North" isn't a real suburb. |
